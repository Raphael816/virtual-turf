# 02. 実装方針と技術構成

## 4. 3Dレース表現と結果シミュレーション

### 4.1 基本の考え方：「シミュレーションが正、映像は再生」

```
seed（秘密）+ 出走表 + 条件 ──▶ シミュレーター（決定論的）──▶ 走行ログ（0.1秒ごとの位置・速度・進路）
                                                            ├─▶ 3Dレンダラー（補間して再生）
                                                            ├─▶ 2D代替表示・順位表
                                                            └─▶ 実況・通過順・上がり3F・勝因の解説
```

- 結果は **レース開始前に1回だけ** 計算し、映像はそのログを再生するだけにします。映像の描画やフレームレートが結果に影響することはありません。
- 同じ seed と入力からは常に同じ結果になります。この性質を使い、レース後に seed を公開して誰でも検証できるようにします。

### 4.2 シミュレーションモデル（0.1秒刻みのエージェントモデル）

| 要素 | モデル化 | 結果への効き方 |
|---|---|---|
| スピード | 最高速度 (m/s)。能力値1あたり約0.012m/s | 直線での伸び |
| スタミナ | 体力の残量 S。消費量は速度比の4乗に比例 | S が低下すると最高速度が落ちる（バテる） |
| 加速 | スパート時の加速度の上限 | 瞬発力、追い込み |
| ゲート | 発走の反応時間。一定確率で出遅れる | 位置取り |
| 気性 | 低いほど「掛かる」確率が上がり、スタミナの消費が増える | 折り合い |
| パワー | 重い馬場やダートでの減速を軽減する | 道悪 |
| 適性 | 距離（最適距離との差）、芝／ダート、道悪をA〜Dで評価 | 最高速度と消費量の補正 |
| 脚質 | 逃げ・先行・差し・追込ごとの目標位置とスパート開始地点 | 展開 |
| 枠順 | 初期の進路（内外）。コーナーで外を回ると距離をロスする（R/(R+d)） | 内枠・外枠の有利不利 |
| ペース | 逃げ馬同士がハナを争うとペースが上がり、前の馬が消耗する | 「前崩れ」「前残り」 |
| 進路 | 前の馬との間隔が狭いと減速するか進路を変更する | 直線で前が詰まる |
| 天候・馬場 | 良・稍重・重・不良。芝は時計がかかり、ダートは逆に時計が速くなる | 道悪適性の差が出る |
| 調子 | レースごとのブレ（正規分布、小さめ） | 意外性 |
| 微小なゆらぎ | 走行中の速度ノイズ | 競り合い |

### 4.3 公正性：乱数・ログ・監査

1. **コミット**：発売開始時に暗号論的乱数で `seed` を生成し、`SHA-256(raceId | seed | engineVersion)` を画面に公開する。
2. **締切**：締切後は購入を受け付けない（購入記録にはタイムスタンプが付き、監査ログに追記される）。
3. **リビール**：レース確定後に `seed` を公開する。ユーザーは「検証」ボタンでハッシュの一致と着順の再現を確認できる。
4. **オッズの推定**：勝率は公開されたシード（`raceId:mc:i`）によるモンテカルロ法で推定する。結果決定用の seed は使わないため、オッズから結果が漏れることはない。
5. **監査ログ**：購入・締切・結果・払戻を、ハッシュチェーン（`hash_n = SHA-256(hash_{n-1} | entry)`）で追記専用に記録する。
6. **エンジンのバージョン固定**：`engineVersion` をハッシュの入力に含め、ロジックを変更したことを検出できるようにする。

> **試作の制約**：MVPは端末内で完結するため、技術的には利用者が自分の seed を覗けてしまいます（デモコインのみなので許容しています）。本番では seed をサーバー（KMS/HSM）だけで管理し、結果もサーバーで計算します。クライアントには締切後の走行ログだけを配信します。

### 4.5 オッズと払戻（パリミュチュエル方式）

```
オッズ = プール総額 × (1 − 控除率) ÷ その組み合わせへの投票額   （0.1倍未満は切り捨て、最低1.0倍）
払戻額 = 賭け金 × 確定オッズ
複勝   = 1 + {プール総額 × (1 − 控除率) − 的中3頭への投票額の合計} ÷ 3 ÷ その馬への投票額
```

| 券種 | 控除率（デモ設定） | 市場プールの規模 |
|---|---|---|
| 単勝・複勝 | 20% | 300万 / 200万コイン |
| 馬連 | 22.5% | 400万コイン |
| 馬単 | 25% | 300万コイン |

- **市場プール**：他の利用者の投票を模擬したもの。配分 ∝ (推定確率 + 下限シェア)^0.92 × 人気の偏り × 時間によるゆらぎ。0.92乗は「大穴が実際の確率より買われやすい」傾向を表す。
- **変動と確定**：発売中は10秒ごとにゆらぎが変わり、締切に近づくほど規模が大きくなり、ゆらぎは小さくなる。締切時点のプールで確定し、以降は変わらない。複勝は確定まで幅（下限〜上限）で表示する。
- **利用者の投票**も同じプールに加算されるため、自分の投票でもオッズがわずかに動く。
- 券種は `src/core/bettypes.ts` に1件追加するだけで、確率推定・オッズ・払戻に自動で反映される。

### 4.4 3D表現

- **コース**：芝（外）とダート（内）の2コース、内ラチと外ラチ、ハロン棒、ゴール板、発馬機
- **スケール感**：大型のスタンド（段差のある観客席と屋根）、インスタンス描画による群衆、照明塔、内馬場の池と木々、遠景
- **馬**：プロシージャルに組み立てた関節モデル（胴・首・頭・脚4本×2関節・尾、騎手、ゼッケン）。ギャロップの位相で脚を動かし、速度に応じて歩幅と頭の上下動を変える。
- **演出**：砂煙のパーティクル（ダートは濃く、芝は少量の芝くず）、雨、夕方やナイターの照明、影
- **カメラ**：自動（中継風にフェーズで切替）／全景／先頭集団（並走）／特定の馬（後方追従）／ゴール前（固定）。補間で滑らかに移動する。
- **画質**：自動・低・中・高。ピクセル比・影・群衆の数・パーティクルの数・アンチエイリアスを切り替える。自動の場合はFPSを監視して画質を下げる。
- **代替表示**：WebGLの初期化に失敗した場合、または2Dを選んだ場合は、上空図（Canvas）と、`aria-live` でスロットリングした順位読み上げに切り替える。

## 5. 技術構成と課題

### 5.1 MVP構成

| 層 | 技術 | 理由 |
|---|---|---|
| フロントエンド | TypeScript + Vite、フレームワークなしのSPA（ハッシュルーター） | 軽量。GitHub Pagesでそのまま配信できる |
| 3D | three.js | 実績が多く、軽量で、WebGL2に対応 |
| ロジック | `src/core/*`（DOMに依存しない純粋なTS） | Node・Worker・サーバーで再利用でき、テストしやすい |
| 保存 | localStorage（スキーマにバージョンを付与） | MVPはサーバー不要 |
| テスト | Vitest | 決定性・払戻計算・上限ロジックのテスト |
| CI/CD | GitHub Actions（型チェック・テスト・ビルド）→ GitHub Pages | |

### 5.2 本番を想定した構成（将来）

```
[Client (Web/PWA)] ──HTTPS/WebSocket──▶ [API Gateway]
                                          ├─ Race Service（出走表・seed のコミット／リビール・シミュレーション実行）
                                          ├─ Betting Service（受付・締切・パリミュチュエルのプール集計）
                                          ├─ Wallet/Ledger（複式簿記・冪等キー）
                                          ├─ RG Service（上限・休止・自己排除・通知）
                                          └─ Audit（追記専用ストレージ / WORM、外部監査用のエクスポート）
   seed: KMS/HSM で生成・保管          走行ログ: CDN で配信（締切後）
```

- `src/core` のシミュレーターはサーバー（Node）でもそのまま動くように設計しています。

### 5.3 性能・運用上の課題

| 課題 | 対策 |
|---|---|
| 低性能なスマートフォンでの3D描画 | 画質の自動調整、ドローコールの削減（インスタンス化）、影をオフ、ピクセル比を上限1.5に |
| 走行ログのサイズ | 0.1秒×16頭×約150秒程度なので小さい。本番では量子化してgzip圧縮 |
| オッズ推定の計算量 | モンテカルロ法用の簡略モード（dt=0.5秒）。本番ではサーバーで事前計算 |
| タブのバックグラウンド化 | 再生時刻は経過時間から再計算し、非表示中は描画を停止 |
| 結果の改ざん防止 | コミット・リビール、サーバーでの権威的な計算、監査ログ、エンジンのバージョン管理 |
| モデルの偏り（人気馬が勝ちすぎる・勝てなさすぎる） | テストで勝率の分布を検証し、人気順の勝率を監視する指標を設ける |
| 利用者保護の運用 | 上限変更の反映遅延（引き上げは24時間後に反映するなど）、サポート窓口、相談先の案内 |
| アクセシビリティ | コントラストAA、キーボード操作、`prefers-reduced-motion`、2D代替表示 |
